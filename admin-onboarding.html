Gurost Admin Onboarding

For the Gurost team — this page won't be linked anywhere public, bookmark it.

1. Access the dashboard

Go to /admin.html. You'll need an x-api-key belonging to an account whose email is in ADMIN_EMAILS (server env var, comma-separated). The key is never saved to your browser — you re-enter it each session, on purpose.

If you get "Admin access only" — check that your account's email in the api_keys table matches exactly what's in ADMIN_EMAILS (case-insensitive, but must otherwise match).

2. What the dashboard shows you

Total Users / Active Users — total is a count of distinct user_id in api_keys; active is anyone with a build in the last 7 days.

Claude Cost (30d) — aggregate across ALL users, not per-user. "Top Users" below is ranked by credits spent instead, which is genuinely per-user.

Revenue (30d) — pulled live from Stripe's charges API, not estimated.

Response Times and Cost Spike — new as of this round; response times come from every request's logged duration, cost spike compares this hour's Claude spend against your trailing 24h average and pushes you a notification if it's more than 3x (adjustable via COST_SPIKE_MULTIPLIER).

3. Managing users

Deactivate an account: POST /api/admin/users/:userId/deactivate (admin-only). This sets revoked = true on their API key row — they're locked out on their very next request, the existing auth check already looks at that flag.

Reactivate: POST /api/admin/users/:userId/reactivate.

There's no admin UI button for this yet — it's API-only in this version. Call it with curl or Postman using your admin key until a UI is built.

4. Viewing errors

The "Recent Errors" table on the dashboard pulls from audit_log where event_type contains "fail" — auth failures, SSO failures, validation failures. It does NOT currently catch every possible server error (500s from routes that don't call security.auditLog) — that's a real gap, not every error path logs to audit_log yet.

5. What still needs your manual setup

  1. 1Run every SQL migration listed across this repo's file header comments — there's no single migration script, each file documents its own tables.
  2. 2Create your Stripe prices (Pro/Unlimited/Ultimate + 3 credit top-ups) and put the price IDs in .env.
  3. 3Set ADMIN_EMAILS before you can access this dashboard at all.
  4. 4If you want Android builds or SSO, those each have their own external account setup — see the main README.md's Android Build and Ultimate Tier sections.
